이 글은 **화면 검토를 위한 샘플**입니다. 실제로 게시할 글이 아니며, 공개 빌드에서 제외됩니다. 코드와 설명이 함께 있을 때 읽는 흐름이 자연스러운지 살펴보기 위해 작성했습니다.

## 코드를 읽는 시간

새로운 기능을 만드는 일만큼 이미 작성한 코드를 이해하는 시간도 중요합니다. 처음에는 간단해 보였던 함수도 몇 주가 지나 다시 읽으면 그때의 의도를 떠올리기 어려울 때가 있습니다. 이름은 충분히 설명하고 있는지, 하나의 함수가 너무 많은 일을 하고 있지는 않은지 천천히 확인합니다.

한 번에 모든 것을 바꾸기보다 작은 단위로 책임을 정리합니다. 입력과 결과를 먼저 생각하고, 실패할 수 있는 상황을 적어 보면 무엇을 테스트해야 하는지도 조금 더 분명해집니다. 이 글에서는 Java의 `Optional`과 작은 조회 함수를 예시로 사용합니다.

### 이름에 의도를 담기

`findPublishedPost`라는 이름은 단순한 `find`보다 많은 정보를 줍니다. 그러나 이름을 길게 만드는 것만으로는 충분하지 않습니다. 실제 동작과 이름이 일치하는지 함께 확인해야 합니다.

```java
public Optional<Post> findPublishedPost(String slug) {
    Objects.requireNonNull(slug, "slug must not be null");
    return posts.stream()
        .filter(post -> !post.isDraft())
        .filter(post -> post.getSlug().equals(slug))
        .findFirst();
}

// 긴 줄은 본문 전체가 아니라 코드 블록 안에서 가로로 스크롤됩니다.

```

## 선택을 표로 정리하기

생각이 복잡할 때는 표로 비교하면 빠뜨린 조건을 발견하기 좋습니다. 아래 표는 모바일에서 표만 가로로 움직이는지 확인하기 위한 예시입니다.

| 선택 | 입력 | 결과 | 실패 상황 | 확인할 내용 |
| --- | --- | --- | --- | --- |
| 공개 글 조회 | 고정 주소 문자열 | 공개된 글 한 개 | 주소 없음 | 빈 결과 처리 |
| 글 목록 조회 | 게시 날짜 기준 | 최신순 글 목록 | 공개 글 없음 | 자연스러운 빈 화면 |
| 이미지 표시 | 상대 이미지 경로 | 본문 안의 이미지 | 파일 누락 | 빌드 오류와 대체 텍스트 |
